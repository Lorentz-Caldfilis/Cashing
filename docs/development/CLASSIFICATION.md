# Cashing 自适应分类：设计与评估

> 2026-09-30 第二阶段：仅将淘宝、京东、拼多多、网购移为中性语境，不再否定明确商品证据。固定场景、来源/学习修复和实测边界见 [第二阶段报告](STUDENT_PHASE2.md)。下文历史基准不是本轮新的盲测。

**状态：** 已实现（schema v3，`classification.py` + `lexicon.py`）。
**依据：** Design Philosophy §2.3、§4、§5、§8；IA §18–§19。本文是 Philosophy §22 所说的 Adaptive Classification Specification 的实现记录，不是冻结规范。

---

## 1. 一句话

> 类别是**派生解释**：数据库只保存用户亲口说过的类别；其余每次读取时由「用户自己的短语 → 内置词 → 不判断」三层现算。证据不够就不判断，而一次例外不会改写一整类记录。

纯标准库，无模型文件，无网络，1 万条用户标注重建约 10 ms，单次判断约 4 µs。

---

## 2. 数据：保存事实，派生解释（schema v3）

| 列 | 含义 |
|---|---|
| `category` | 只存**用户说过**的类别；NULL = 用户没说过，或用户选了“暂未判断” |
| `category_by_user` | 0/1。`(NULL, 1)` = 用户明确选了“暂未判断”；约束 `category IS NULL OR category_by_user = 1` |

- 软件自己的判断**从不写回数据库**：模型不会拿自己的猜测训练自己；算法改进后，全部历史自动按新解释显示；数据库里只有事实。
- 迁移：v1（每条都由用户选过类别）与 v2（只会复制用户自己的类别）中已有的类别全部视为用户的；v2 的 NULL 留给软件判断。迁移前在同目录生成 `ledger.sqlite3.before-v3.bak`，单事务重建，失败回滚。
- `Ledger` 在 `month()` / `search()` 时从已存标注重建分类器（1 万条约 20 ms 含查询），每条记录读取时派生 `category`；UI 继续只读 `record["category"]`。编辑后 `Ledger` 增量同步，Review 就地更新其他行（`HistoryList.reinterpret`），不重建列表。

## 3. 算法

**分词**：NFKC、小写；汉字逐字，其他字母/数字连续串为一个词（`gpt` 不会命中 `chatgpt` 内部）；标点、空格、emoji 忽略。短语 = 词序列。

**第 1 层：用户自己的短语（投票）。** 同一短语的每条用户标注是一票：最新一票权重 1，更早的每条 ×0.85（`RECENCY`）；该短语的内置判断另加 0.8 票（`PRIOR`，略少于用户一票）。第一名须 ≥ 第二名的 2 倍（`DOMINANCE`）才算数；否则有内置判断就维持内置判断，没有就不判断。“暂未判断”也是一票。

| 情况 | 结果 |
|---|---|
| 第一次标注一个新词（奶茶 → 娱乐） | 立即学会，所有“奶茶”记录按此显示 |
| 生日那顿午饭标为娱乐（一次例外） | 其他午饭仍是生活 |
| 同一短语第二次同样纠正 | 改为用户的类别 |
| 用户改变主意（3 次工具后开始标生活） | 2 次时不判断，4 次后改为生活 |

**第 2 层：文本里的短语，最长匹配。** 用户标注过的短语（≥2 字符，≤12 词）和 `lexicon.py` 的内置词一起做正向最长匹配，同长度时用户的优先。所有命中必须一致；出现用户“暂未判断”的短语，或出现内置 `AMBIGUOUS` 词（奶茶、咖啡、零食、书、耳机、健身……）而文本中没有用户自己的短语时，不判断。`NEUTRAL`（面试、见面）只占位，不给证据。

**第 3 层：不判断。** 不是待办，不提示（Philosophy §4.3）。

**内置词（`lexicon.py`）**：只收几乎所有学生都会同样归类的词，约 500 个；另有“中心字”规则（汉语复合词中心在后：…面/…粉/…汤/…煲、烤/炒/炖/焖、衣/裤/袜、车），靠最长匹配的更长词作护栏（吃鸡、面包板、车模、面试）。因人而异的词**不给类别**，只作阻断。

## 4. 评估方法

`scripts/classification_benchmark.py`（确定性、合成数据，不读取任何真实账本）：

- 约 80 个日常消费条目（带频率权重与写法变体）+ 长尾：HARD（开发 DEV / 测试 TEST 两半）、FRESH（规则定稿后才写、只评估一次）。30% 记录来自长尾，30% 带中性修饰（和室友、x2、补记……）。
- 人物 A/B/C 在因人而异的条目上意见不同；D 还在三个高频条目上反对内置词（火锅→娱乐、打车/话费→工具）。
- 180 天，每天约 4 笔；每周回看一次：错误以 0.7 概率纠正，“暂未判断”以 0.25 概率补标；标签为 None 的条目用户永不标注、也不希望被猜。
- 指标：**精确率**（软件判断中正确的比例）、**覆盖率**（非用户标注记录中软件作出判断的比例）、**错误率**（显示错误类别的记录占比）。按“创建时”与“第 1 / 第 6 个月 Review 实际显示”分别统计。

> 局限：数据由实现者编写，词表与测试集存在不可避免的同源偏差；FRESH 与“中心字”规则的首轮结果（见 §5.3）是最接近无偏的估计。真实用户数据未使用，也不应被开发过程读取。

## 5. 结果

### 5.1 最终方案（`python scripts/classification_benchmark.py`，人物 A–D × 5 种子）

| 场景 · 长尾 | 创建时 精确 / 覆盖 | 第 1 月 | 第 6 月 |
|---|---|---|---|
| 新用户 · TEST | 98.9% / 72.8% | 99.6% / 73.6% | 99.2% / 81.6% |
| 新用户 · FRESH | 98.4% / 77.2% | 99.3% / 77.5% | 99.4% / 83.2% |
| v1 升级（前 60 天全标注）· TEST | 98.9% / 80.9% | 99.4% / 82.1% | 99.4% / 85.1% |
| v1 升级 · FRESH | 98.9% / 84.4% | 99.5% / 85.6% | 99.6% / 87.6% |
| 新用户 + 3% 刻意例外 · FRESH | 95.4% / 77.3% | 98.6% / 77.4% | 98.7% / 84.3% |

（有例外时“创建时”约 2.3% 的错误来自例外记录本身，任何方法都无法预知。）对照：当前 v2 行为（仅相同说明沿用）第 6 月覆盖率约 30%。

剩余错误主要是：混合购买（午饭+奶茶、超市买零食和水，本基准要求不猜）；中心字误伤（鱼缸、车模 → 已加护栏/移除 鱼）；与内置词冲突、尚未被纠正两次的个人习惯。

### 5.2 候选方案对比（同一模拟器；新用户，DEV/TEST 长尾）

| 方案 | 结论 |
|---|---|
| 仅相同说明（v2） | 精确 100%，覆盖 15%→32%。太保守，“越用越懂”几乎不发生。 |
| 相同说明 + 内置词 | 精确 ~99%，覆盖 69%→75%。主要收益来源。 |
| 字符 n-gram 朴素贝叶斯 | 创建时 98.4% / 49%。一次标注泄漏到子串（标“面包板”后“面包”变工具，“同学”“电子”同理）。 |
| n-gram 决策表 / bigram 关键词 | 有了个人短语后覆盖 +0.5%，标注越多精确率越低 → 去掉。 |
| TF-IDF 字符 1–3gram + 逻辑回归（sklearn，仅作参照） | 覆盖高（85–93%）但精确 93–98%；冷长尾精确仅 66%。每次约 1 ms，需 numpy/scikit-learn。 |
| 个人短语词典 + 内置词（最新一票定） | TEST 第 6 月 99.3% / 78.2%。 |
| + 中心字与模糊词阻断 | FRESH 冷长尾 22→35 条正确；整体覆盖 +2.5–3 点，精确不变。 |
| 最新一票定 vs **投票** | 无例外时相近；3% 例外时第 6 月错误率 1.9%→0.7%（DEV）、2.0%→1.6%（FRESH）。“最新一票定”下一次例外把所有“地铁”变成工具、“公交”变成娱乐。 |
| + 隐式接受（未改动的记录算弱赞成） | 无稳定收益，且需统计全部记录 → 去掉。 |
| + 内置词被用户短语反向投票 | 中性 → 去掉；用户直接标注该词即可覆盖。 |

常数敏感度：`DOMINANCE` 1.5–3、内置权重 1.5–4、`PRIOR` 0.5–1.5、`RECENCY` 0.7–1.0 范围内结果平缓，没有刀刃点；所选值在有/无例外两种情况之间折中。

### 5.3 中心字规则的无偏估计

FRESH 写于规则之后、只评估一次：仅内置词时每人 22–24 对 / 0–3 错（81 条）；加中心字与阻断后 35–36 对 / 2–3 错，冷长尾精确约 92–95%。其后移除了 `鱼`、增加了 `车模` 护栏，当前为 35 对 / 1 错。

### 5.4 Embedding 与本地小模型

- 本机没有可用的中文向量模型或 LLM，本轮**未做实测**（未下载任何模型）。
- **上限分析**：第 6 月仍未判断的记录中，通用长尾词约占全部记录 10.5%，这是任何通用语义模型能增加的覆盖率上限；另有 6.6% 是因人而异（通用模型不可能知道），3.4% 本就不该猜。
- **成本**：bge-small-zh 级模型需 onnxruntime + numpy + 约 25–100 MB 权重，发行包约从 115 MB 增至 200 MB 以上，并带来冷启动；本项目已为瘦身移除 numpy。字符相似度方法在短中文上的精确率（上表 66–98%）也提示语义近邻需要很高阈值才能满足“高置信才分类”。
- **本地 LLM**（0.5B 量化约 400 MB，CPU 每次数百毫秒）：违背 Philosophy §4.6 与轻量目标，不进入 Core。
- **结论**：Core 不采用。若日后作为可选扩展，最合适的位置是第 2 层之后、仅在内置词与个人短语都没有证据时，对长尾给出高阈值判断；评估可直接复用本基准的 FRESH/TEST 与“上限”统计。

## 6. 测试

- `tests/test_classification.py`：分词、内置词/护栏/中性/阻断、个人短语即时学习与最长匹配、例外与两次纠正、改变主意、“暂未判断”投票、标注移动与删除、顺序决定新旧，以及一个两种子的基准回归（阈值略低于实测）。
- `tests/test_ledger.py`：只存事实、派生显示、例外不扩散、“暂未判断”保持、修改说明后重新派生、标注随记录移动、删除/撤销保留用户说过的话。
- `tests/test_migration.py`：v1→v3 全部视为用户类别；v2→v3 保留 NULL 给软件判断；备份、回滚、只迁移一次。
- `tests/test_ui_edit.py`：界面上“暂未判断”刷新后不被重新派生；纠正一条后同月其他同短语记录就地更新、不重建。

## 7. 已知限制与后续

- “最新”按 `updated_at` 排序：修改一条已标注记录的金额也会让它的标注变“新”。只影响票权的轻微衰减。
- 没有“恢复自动判断”的操作：用户一旦选过类别，该记录就保持用户的选择（与 IA 的“用户可直接修改”一致，不新增 UI）。
- 内置词是一份人工词表，面向中国大陆学生消费；扩充应先在基准的 DEV 上验证，再用新写的长尾评估一次。
