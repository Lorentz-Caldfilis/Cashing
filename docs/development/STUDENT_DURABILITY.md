# 耐用性验收（实现前目标）

起点 bd945e6；仅隔离合成数据库。先固定 10,000 条跨 24 个月记录，另测单月密集 10,000 条。
80% 自动/20% 人工分类；重复说明与带编号新说明混合。每种场景最多一次基线、一次修复后复测。
Linux 当前容器、Python/Qt/CPU/内存、提交、缩放在 JSON 中记录；时间为 perf_counter 墙钟，
GUI 操作包含 processEvents 完成布局，RSS 从 /proc/self/status 读取，非 Windows 物理设备性能。

本机接受目标：初始化和首屏 <2s；普通月份/窄搜索 <1s；宽搜索或密集月份首屏 <2s，
额外 RSS <200MiB。总数和统计必须完整；如果分批显示，必须明确可继续查看，不能静默截断。
不将机器相关毫秒阈值写成易波动的 CI 断言；回归测试验证有界控件数、结果完整和编辑状态。

额外状态验收：100 轮纠错→自动→撤销→撤销，恢复原始数据及个人标签；
备份复制到全新数据目录，重新初始化并核对全部事实、标签、月统计。
v1/v2 合成账本升级后验证迁移备份仍为原 schema；说明旧程序回退只用升级前副本，
不对 v3 文件做反向转换。升级后的新增数据不会自动回到旧副本。

不跑无限压力循环，不读取用户账本，不为了分数修改分类语料。

## 实測结果与最小修复

机器及测量明细见 evidence/durability-20260930 的 JSON（Linux/X11、100%）。
同一 10,000 条数据生成器，跨 24 月与全部集中于一月分别测量；20% 人工标签。
基线发现数据库不是主要瓶颈：初始化约 0.07s，月服务 0.01s/0.27s。
原 UI 为全部结果建立 QWidget；密集月份启动 32.65s、RSS 1906 MiB，宽搜索 6.07s。
基线密集进程已完成 JSON/截图输出，但销毁大量控件时超过外部 90s 上限，退出码 124；不隐去此失败。
跨月宽搜索 5.07s，增加 300.57 MiB。

仅增加 Review 分页（每页 60 条），不改数据库查询或统计，不引入异步线程/大重构。
列表下方明确显示范围、总数、上一页、下一页；新月份/搜索回到第一页；编辑错误阻止翻页；
删除末页最后记录会回到有效页。全部月总额保持完整，人工学习仍作用于全部记录。

启动仍高于预设 2s，包含首次 Qt/font/window 显示成本；本轮未进一步归因，不能宣称启动目标全部通过。
跨月基线有 Fontconfig 缓存目录警告，修复后指定可写缓存；性能改善同时受该环境差异影响，
密集基线与复测均使用同一可写缓存。控件数限制和内存大幅下降有直接因果回归支持。
基线 broad_search_service 误用空查询，数字不作对比；GUI 宽搜索实际查询“食堂”，前后相同。

两种数据形状各完成 100 轮纠错→自动→撤销→撤销，无额外标签遗留。
备份约 0.008–0.009s；新目录恢复后的全部 10,000 条原始事实、2,000 条标签和月统计相等。
另以恢复目录实际启动 GUI：显示 10,000 条、60 个当前行、总额 25,995,000 分，截图/JSON 留存。
现有 v1/v2 升级测试加 fresh legacy-copy 回归：原备份 schema/事实保留，升级后新增数据不出现在旧副本。
只验证 SQLite 兼容和重新升级，没有运行旧版 v1 二进制。

回退：revert 本批 UI 分页提交即可恢复原全量控件显示，不涉及 schema；大数据性能问题会随之恢复。
脚本 `scripts/verify_durability.py --label <新名称> [--dense]` 只写 ignored work，拒绝复用目录。
脚本为人工有界验收，不加入每次 CI 的高成本性能压测；CI 验证分页状态与数据正确性。

最终 Linux 全量 400 tests / 31.42s，四个 X11 GUI 进程通过；Capture/Review/空态/长错误/恢复分页截图已归档。
